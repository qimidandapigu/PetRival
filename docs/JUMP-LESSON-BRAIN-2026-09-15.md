# 示范课的学习重构：字符地图、不教通关、动作序列、经验→规则

基线：origin/main `84ae62c`。`git fetch origin` 仍失败（远端 `Repository not found`）。

## 玩家指出的四个问题（都成立）

1. **"至少要给二维关卡信息，一个数组，平台/空/水/钥匙"** —— 之前给的是平台矩形列表，等于让它读 CAD 图。
2. **"不用告诉它怎么通关，也不用给目标常量"** —— 之前提示词把物理常量和"先钥匙→踩开关→收金币"的顺序都告诉了它。
3. **"它输出的应该是动作序列"** —— 它本来就输出按键序列，但被"只做 20–60 帧局部目标"切碎。
4. **"示范不是光动，学习要有总结出来的知识"** —— 之前示范只是原始按键，没有变成规则。
5. 附带的自我批评：**世界模型那套（Schema 类做法）只做在空白实验室，玩家玩的示范课里没有。**

## 这轮改了什么

- **字符地图当画面**（`public/jump-world.mjs` 的 `tileMap`）：每格 16 像素、30 行，`#` 地面/平台、空格空气、`~` 水、`c` 金币、`k` 钥匙、`s` 机关、`D`/`d` 关着/开着的门、`G` 终点、`@` 它自己；地面画到屏幕底部，高台是薄的一层。图例随图一起给出（"这是金币、这是水"），但**不给通关顺序**。
- **提示词重写**（`LESSON_SYSTEM`）：删掉物理常量、删掉通关顺序、删掉"走到坑边前停下"；只留图例、三个按键的用法、"目标只有一个：让 progress.won 变成 true"、以及"同一个地方失败两次以上必须换做法"。允许**一次输出一整段连贯动作序列**（≤12 段 / ≤240 帧，含助跑、起跳、空中调整）。
- **超预算不再作废**：`fitActions` 按 240 帧截断但保留计划（形状错误才拒绝），避免整轮白费。
- **经验记忆**：它每次执行完都会记一条 `attempt`（起点、动作、终点、跌落/存活），最多 8 条，随决策上下文一起发送并显示在右栏；日志新增「它的尝试」分类。
- **经验→规则**：演示结束自动触发、也可按「让它总结这一关」手动触发 `POST /api/jump/lesson/learn`：把示范 + 它的尝试总结成这一关的规则，服务端仍按证据条数决定状态（3 条以上证据→确认）。规则存浏览器、随决策发送、显示在右栏。
- **修复一个真 bug**：之前总结时我没有给尝试编 id，模型无法引用证据，导致**所有规则永远停在「猜想」**——这就是"一点也没学习"的直接原因之一。

## 真实模型验证（2026-09-15，本地 Node，`deepseek-v4-pro`，第 2 关「学会跳」，80 像素小溪）

- 它能从字符图里读出东西：提到"水（~）会导致死亡"、"尝试越过可能的水域"、"观察地图中右侧物体"、"金币可以收集"，说明它是在读画面而不是背我给的顺序。
- 三轮尝试都没到小溪（结束于 x≈224–272），动作退化成"短跳 + 右移"的重复节奏；**没有跨过去**。
- 总结这 6 条规则**全部达到「确认」**（各 3 条证据）：水会致死 / 连续跳跃可以跨越水区 / 金币可收集 / 钥匙可收集 / 门需要钥匙 / 到达终点通关。它们正确但很浅，**没有一条是量化的**（例如"80 像素的空隙要按住跳多少帧"）。

## 还没做到的（下一步的真实工作）

- **它仍然学不会跳那条溪**：三百万帧级的问题不在"看不见水"，而在没有量化规则 + 没利用失败。两个具体原因：
  1. 我记录的 `attempt.from` 是**本轮开始**的状态，不是**起跳前**的状态，所以它看不到"我在 x=420 起跳、落在 x=461"这种可用信息。要记录起跳瞬间的状态。
  2. 总结提示词没有要求**量化**（"空隙多少像素、要按多少帧、跳多远"），所以产出的是通用常识级规则。
- **世界模型（代码形式）还没进示范课**：目前只在空白实验室。把它接到示范课是下一个独立任务。
- 没有难度自适应；一次决策仍受 16 次调用上限约束。
