# 小精灵跳跳课：分屏（它上我下）与「重开一轮」

基线：origin/main `d2c871d`（学习日志）。`git fetch origin` 仍失败（远端 `Repository not found`），以本地 `origin/main` 为基线。

## 为什么要加

玩家要求：**"能不能分屏它上，我下，我们两个都闯关，然后我可以不断重新开始不断地示范"**。原来只有一个镜头，两个人一分开就必然有一个人跑出画面；而"重新开始"用的是整关重置，虽然保留了学习，但过程里看不出这是第几轮、这一轮示范了几次。

## 行为

- **分屏（默认开启）**：同一个世界、同一份进度、两个镜头。上半屏镜头跟小精灵，下半屏镜头跟你，各自平滑跟随、各自拉边。两个窗格都画出**两个角色**，所以任何时候都能看到对方离你多远；每个窗格右上角标明"镜头跟小精灵 / 镜头跟你"，中间有一条分隔线。取消勾选就回到原来的单镜头模式，此时由「镜头」下拉框决定跟谁。
- 关掉分屏时画布高度回到 470；开启时是 940（两个 470 的世界窗格 1:1 渲染，不缩放）。
- 分屏开关与"自动重开"开关记在当前浏览器（`petrival.jump.split.v1`），下次打开保持你的选择。
- **「重开一轮（保留学习）」**：把你们两人都放回出生点、清空关卡目标与模型调用计数，**保留**机制手册、实验轨迹、世界模型、你的示范笔记和成绩曲线。实验室模式下还会在学习日志里写一条「重开」记录，写清保留了多少条手册、多少次实验、多少次调用。轮次与"本轮示范 N 次"显示在工具栏上。
- **「它摔了就自动重开一轮」**：小精灵跌落会先在画面上停留约 1.5 秒（90 帧），然后自动重开一轮，你直接点「回去示范」就能接着教。默认关闭。
- 「示范完成，让它试」按钮仍然是录完立刻让它跑，所以"重开 → 示范 → 它试"是三步一循环。
- 经典示范课的「本关重来」现在也走同一条路径（轮次递增 + 日志），换关或换实验室世界时轮次回到第 1 轮。

## 验证记录

- 自动化：193 项 Node 测试（新增 3 项：分屏渲染两个裁剪窗格且两个镜头偏移分别是 0 与 470、画布高度在 470/940 之间正确切换、开关写入本地；重开一轮保留手册与轨迹而清空位置与目标并递增轮次；跌落 1.5 秒后自动重开把两人放回出生点），40 项 Cloud 测试、`npm run check` 0 失败、`npm run build` 通过。
- 页面夹具用带记录的 2D 上下文断言了绘制调用：`clip` 两次、`translate` 的 y 偏移为 `0` 与 `470`、每个窗格各写一次"镜头"标签。这验证的是绘制契约，不是观感。
- 未做：真实浏览器观感确认（没有浏览器自动化）、线上发布。分屏让画布高度翻倍，手机竖屏下会很占屏幕——这是设计取舍，不是 bug。

## 限制

- 两个窗格渲染的是**同一个世界状态**，不是两个独立世界；你们仍然互相看不见对方造成的改变（金币和机关只有小精灵能触发，这是既有规则）。
- 只有一个 canvas：分屏是两次裁剪绘制，不是两个独立元素，所以无法各自全屏或拖拽分隔线。
- 「自动重开」按帧计时（90 帧 ≈ 1.5 秒），没有做成可配置。
