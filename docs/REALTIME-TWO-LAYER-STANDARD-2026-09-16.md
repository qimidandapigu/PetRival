# 系统标准：推演层 / 播放层（实时两段式）

基线：origin/main `16d1e04`。`git fetch origin` 仍失败（原远端不可达）；当前 `origin` 已指向 `qimidandapigu/PetRival`（私有）。

## 问题

模型一次调用几秒到十几秒，游戏一帧只有 16 毫秒。串行做就是"等一等、动一动"：现在横版是队列播完 → 停 → 等模型 → 再播。玩家看到的节奏由模型的延迟决定，而不是由游戏决定。

## 标准方案

两层，三个游戏共用：

- **推演层**：模型一给出动作，立刻用**引擎**（毫秒级、与播放完全同一份物理/规则实现）把它推演到底，得到逐帧预期状态、结束状态与进度；推演完**马上**用推演出来的状态接着问下一轮。思考和推演始终跑在播放前面——玩家看到的其实是已经算完、已经核对过的胶片。
- **播放层**：只负责按帧播放缓冲里的胶片，并在每一帧核对"实际 == 推演预期"。对不上说明世界变了，**整段作废**并立即重算，绝不把错的胶片播完。

### 共用模块（`public/lookahead.mjs`，纯函数、已测）

```js
import { createBuffer, simulate, matches, toBlock, WATER } from '/lookahead.mjs';

const buffer = createBuffer({ high: 600, low: 180 });       // 水位：10 秒停止思考，3 秒继续
const rolled = simulate(step, { level, actor, progress, actions, physics, role });   // 推演
buffer.push(toBlock(actions, rolled));                       // 入缓冲（超过上限会被拒绝）
while (buffer.needsThink()) await askModel(rolled.end);      // 边播边想：不需要等播放

const frame = buffer.next();                                 // 播放一帧
step(live, frame.action, level, p, role);                    // 真的执行
if (!matches(frame.expected, live)) { buffer.drop('与推演不符'); /* 立刻重算 */ }
```

设计要点：

- **水位**：`high` 之上停止思考（省 token），`low` 之下恢复；`maxFrames` 是硬上限，溢出直接拒收而不是悄悄截断。
- **逐帧核对**：`matches` 比较 x/y/vy 与是否落地；任何一帧对不上就丢弃剩余胶片并重算。
- **重规划触发**（四个，必须都实现）：块正常播完 / 推演与实际不符 / 世界变化（金币被吃、门开了、关卡换了）/ 玩家点「接管」。
- **不空播**：缓冲没有胶片时，精灵显示"正在想"，而不是随机乱动。

### 可测指标（别只说"感觉流畅"）

| 指标 | 现在 | 目标 |
|---|---|---|
| 等待次数 / 分钟游戏时间 | 约每 4 秒游戏时间等一次 | ≤ 1 次 / 20 秒 |
| 单次等待时长 | 4–13 秒 | 不阻塞播放（0） |
| 播放覆盖率（有胶片可播的帧占比） | 串行下明显低于 1 | > 95% |
| 计划失效率（被丢弃的胶片占比） | 未统计 | < 5% |
| 每千 token 的有效游戏时长 | 未统计 | 逐版本上升 |

## 各游戏怎么接（三个游戏同一套接口）

| 游戏 | 推演层用什么当 `step` | 播放层播什么 | 现状 |
|---|---|---|---|
| 横版跳跃 `/jump` | `public/jump-world.mjs` 的 `step()`（已有） | 60fps 逐帧按键，分屏两栏各自核对 | **本模块已就绪，接线待做** |
| 推箱子 | `public/sokoban.mjs`（或对应规则模块）的走一步/推一箱；模型本来就返回整串方向动作，天然是"胶片" | 逐格动画（每步 N 帧插值），播放期间推演下一串 | 待接线 |
| 打拳 | 拳台规则模块结算一回合（`server/boxing-arena.mjs` 的判定） | 回合动画：把已经结算完的这一回合演出来，动画期间算下一回合 | 待接线 |

推箱子和打拳还有一个**额外的便宜好处**：它们的规则判定是纯函数、毫秒级，所以推演层可以在**播给玩家之前**就把模型给的动作串整段跑一遍（推箱子：能推到位吗？会不会推死？打拳：这一手会不会被打中？），不合格就立刻重问，而不是让玩家看着一段注定失败的操作演完。横版那边同样适用（`fitActions` + 引擎预校验）。
