# 小精灵世界模型即代码（world-model-as-code）

基线：origin/main `c7dc445`（空白实验室）。本次仍未能在本机 `git fetch origin`（远端返回 `Repository not found`），以本地 `origin/main` 为基线。

## 为什么做这一步

空白实验室原来的"机制手册"是**散文式结论**：模型写「按住 a 会让精灵向上跳」，服务端只能数它引用了几个实验 id，无法判断这句话对不对。玩家问的是"至少有个学习机制吧"，指向 [Schema 的 ARC-AGI-3 harness（world-model-as-code）](https://github.com/Cargo-Cult-Research/schema-qwen)、[TWIN: 用测试时数字孪生玩未知游戏](https://export.arxiv.org/pdf/2608.14490)、[Tycho: 程序化世界模型](https://ar5iv.labs.arxiv.org/html/2607.28287) 这一族做法：**让模型把世界规律写成可执行代码，用真实数据反复运行它、量误差、按分歧去修**。这一步现在实现了。

## 行为

- 新增按钮「④ 写成可执行世界模型」与「⑤ 用它的模型过坑」。接口契约：模型只写一个函数 `step(state, action, level)`，返回**下一帧**状态 `{x, y, vy, grounded, held}`；`state` 含位置、垂直速度、是否落地、上一帧通道状态，`action` 是 `{a,b,c}` 三个布尔通道，`level` 是关卡几何。
- 服务端在 **`node:vm` 新上下文**里运行它：只允许 `Math`/`JSON`，禁用字符串代码生成与 WebAssembly，所有数据以 JSON 内联进脚本，**不传任何宿主对象**进去；整段脚本一次运行、硬超时 1.5 秒。写到死循环只会得到"运行超时"，拿不到 `process`、`require`、`globalThis.process`。
- **评分是量出来的，不是自报的**：把模型代码在每条真实实验上逐帧 rollout，和记录的每个采样帧比较（x 容差 1.5、y 2、vy 1.5，落地状态必须一致），返回对上多少帧、最差偏差倍数、**第一处分歧**的预测值与真实值，以及这一处分歧是否落在某个通道的按下/松开边沿上。
- **修复循环**：写 → 跑 → 拿分歧 → 只改那一处 → 再跑，最多 4 轮。第一轮失败会重试一次（避免一次网络抖动毁掉整个请求）；后续轮次失败则保留已取得的最好一版并说明原因。**只有 0 误差才叫通过**。
- **通过才允许规划**：验证通过的模型会被放进模型内 A* 搜索（8 种通道组合掩码 × 4 种按住长度，搜索本身不知道通道含义），找出从精灵当前位置到目标 x 的动作序列与预测落点。未通过的模型不给规划，不给任何"大概能行"的结论。
- 「⑤ 用它的模型过坑」把这份规划交给**真实引擎**执行，用真结果给模型打分：预测落点与真实落点差 40 像素内且没跌落才算成立；无论成立与否，这条真实轨迹都会以 `origin: self` 进入证据表，供下一轮修复。这也是"精灵自己的尝试变成证据"的落地。
- 证据格式同时改了：实验轨迹现在**逐帧**记录（落地与松开截断都发生在单帧内，稀疏采样正好藏掉最难推的两条规则）、保留 3 位小数（否则常量根本读不准）、裁掉尾部静止帧（不裁会占满提示词）。HTTP 请求体上限从 32768 提到 65536 字节（Node 与 Worker 同步）。

## Node / Sites 边界

`node:vm` 是 Node 能力。`server/jump-world-code.mjs` 与 `server/jump-world-api.mjs` **不进 Worker 的导入图**：Worker 对该路由明确返回 503「世界模型沙箱只在本地 Node 服务可用」，其余实验室功能在两端一致。没有数据库结构变化，没有改动身份、积分与既有游戏。

## 验证记录

- 自动化：188 项 Node 测试（新增 7 项）、40 项 Cloud 测试、`npm run check` 155 文件 0 失败、`npm run build` 通过。新增覆盖：真值模型的逐帧复现、错误重力被抓在第一处分歧、**4 种沙箱逃逸尝试全部失败且不泄漏**、死循环超时、验证通过的模型自规划且真引擎结果一致、修复循环用分歧把错模型修成 0 误差、从不匹配的模型如实报告且永不规划、UI 全流程（发轨迹 → 存代码 → 真引擎执行规划 → `self` 轨迹入证据）。
- 真实 DeepSeek 检查（2026-09-15，本地 Node，`AI_MODE=model`，`deepseek-v4-pro`，两个世界各 4 轮修复，每轮约 7–13 秒）：模型能**逐帧读出全部常量**——重力 0.56 / 0.64、每帧位移 2.93 / 2.92、跳跃初速、x 最小边界 12、平台高度 336 与 400，全部与隐藏真相一致；世界一最终 **255/258 帧对上（误差 0.012）**，并在自己的 notes 里写出了从数据推出来的松开截断规则：「释放跳跃键 a 时，如果当前 vy < 0，vy 被重置为 -2.3（从 eng-a-tap 第 7 帧 vy 由 -10.02 变为 -2.3 得出）」。
- **同一次检查也证明它还不收敛**：世界二 4 轮后仍停在 247 帧里错 56 帧（误差 0.227），它正在手工推导松开后的额外增量（"第7帧 vy=-5.29，第6帧 vy=-8.96，差值为 +3.67…"）但没用完轮次。两个世界都**没有达到 0 误差，因此没有产出任何规划**，页面上显示 ✗ 未通过——这正是这条机制的完整性：不通过就不给结论。
- 中途失败过的假设（已修）：模型会把世界当连续时间（`dt=1/60`、174 px/s）→ 在接口语义里写明"逐帧离散、没有 dt"；模型会发明终端速度与摩擦 → 写明"表里没有的机制不要写"，并用逐帧数据让这类发明立刻暴露；我自己把采样四舍五入到 0.1 位 → 导致常量永远读不准，改为 3 位小数。
- 未做：真实浏览器实玩（只有页面夹具）、线上发布、整关通关。`test/life.test.mjs` 与 `test/boxing.test.mjs` 在本机偶发 `EPERM rename`（在未改动的 main 上单独运行即复现），与本改动无关。

## 已知限制

- 4 轮修复对这两个世界不够。要收敛需要更多轮次、更强的模型，或更结构化的修复协议（例如让模型只输出一个"补丁"而不是整段代码）。
- 模型仍会引入表里没有的机制（终端速度、摩擦、连续时间积分）。目前靠"逐帧数据 + 明确禁止 + 首处分歧"压制，没有形式化保证。
- 规划目前只针对"从当前位置到目标 x"的移动问题：世界模型只建模运动学，不知道金币、钥匙、开关与门的语义。
