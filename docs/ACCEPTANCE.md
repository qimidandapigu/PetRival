## 已执行的测试

在仓库目录运行：

```sh
npm test
npm run check
git diff --check
```

当前 20 项测试通过，覆盖：

- 严格地图校验，移动 / 推箱 / 撤销 / 重开，同一个引擎执行合法动作与胜利判定。
- 80 个生成种子逐个回放通关，随机多样性与确定性；无解和搜索预算耗尽分别处理。
- 真实 HTTP 服务、独立访客 Cookie、两只玩家宠物：创建、预生成、即时挑战、两只参赛 AI 执行、真人通关与认输、一次性结算和排行。
- 分数相同比服务端计时；客户端伪造分数、时间或胜利没有效力。
- 跨用户越权、跨站请求、敏感静态路径、重复领养和重复对手挑战均被拒绝。
- 真人计时不被重复 start 重置，超时正常失败，无人上线的对局作废且不扣分。
- 训练宠物不伪造真人成绩，不进入正式排行。
- 服务对象关闭并重新创建后，访客身份、关卡快照与开始时间从真实落盘存档恢复。
- 外部模型仅在 HTTP 服务边界模拟，仍经过实际 provider、队列、校验、游戏引擎和结算链路；没有把执行器 mock 成“成功”。
- 出题模型被故意挂起时仍可立即创建缓存关卡挑战；解除挂起、换题后本局地图版本不变。
- 模型出题失败保留旧题；模型非法动作计失败；供应商 HTTP 故障作废，不错误扣分。

`npm run check` 为语法检查与基本密钥模式检查，不是完整安全审计；没有 GitHub Actions / 分支保护自动硬门禁。

## 开发中抓到并验证的三个问题

| 问题 | 修复前的行为断言 | 修复后 |
| --- | --- | --- |
| 轮询重复注册保留的表单 | 一次提交实际产生 10 次请求，期望 1 次；ui-binding 用例失败 | 替换旧监听器，同一用例通过 |
| 通关提交响应丢失后无法补交 | 重新进入已解完但未确认的对局，补交次数 0，期望 1；用例失败 | 读取已保存合法操作后自动补交，服务端仍幂等 |
| 非法模型操作被误当作服务故障 | 实际 HTTP 模型返回 WIN，挑战变成 void，期望继续并记录宠物失败；用例失败 | 分开模型输出错误与请求传输故障，同一用例通过 |

页面事件测试执行生产入口的绑定和恢复代码，仅模拟 DOM / 网络边界，不代表全套浏览器自动化。

## 实际浏览器验证

在本机 `http://127.0.0.1:4388` 的真实浏览器中：

1. 页面实际加载，原创像素角色、领养表单、宠物卡片和榜单可见。
2. 领养“栗子”，已有守擂关立即可用，随后后台备题完成。
3. 点击训练宠物“薄荷”发起挑战，进入已锁定的地图、出现 3 分钟真人计时。
4. 根据屏幕可见棋盘计算操作路线，通过实际方向键输入 16 步完成关卡，不修改前端状态或绕过服务端提交。
5. 页面显示主人 +100、宠物 +100、训练完成 +200，训练分不计入排行榜。
6. 检查页面截图，棋盘、操作按钮、双方状态与结算信息均可见；所读取浏览器错误 / 警告日志为空。

该项是代理通过真人操作入口进行的浏览器冒烟验证，不是用户本人验收；双真人身份对战由 HTTP 集成测试覆盖，没有冒称两个真实用户已经在线比赛。
