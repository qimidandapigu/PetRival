# 小精灵跳跳课：两个独立玩家 + 日志挪到左栏

基线：origin/main `2f79986`（分屏）。`git fetch origin` 仍失败（远端 `Repository not found`），以本地 `origin/main` 为基线。

## 为什么要改（玩家原话）

1. **"日志呢，我在哪看，能不能比如就在左边那列"** —— 日志原来埋在实验室区最下面的折叠块里，得往下滚才看得到。
2. **"我和小精灵是独立的，小精灵的是小精灵的，我的是我的，所以我应该能吃金币之类的"** —— 原来的引擎规定只有小精灵能触发金币、钥匙、开关（`touch()` 对非 pet 角色直接返回），人类只能看。
3. **"我和小精灵死的话都应该复活重新开始才对"** —— 原来人类死了自动回出生点，小精灵死了会停下等你点"开始"。

## 行为

- **两个独立玩家**：`step()` 和 `touch()` 不再按角色区分，谁被传进哪个 progress 对象，谁就在那个对象上收金币、拿钥匙、踩开关、开门、通关。页面为两边各留一份：`humanProgress` 与 `progress`。你收你的，它收它的，互相看不见对方的分数。
  - 门槛也各算各的：机关没开时挡的是"还没开门的那个玩家"，不是"人类一律不许过"。
  - 顶部目标栏显示两边进度：`你 金币 1/3 · 已取钥匙 · 门已开　|　小精灵 金币 0/3 · 先取钥匙 · 回头开机关`。
  - 你自己通关时会写进日志与状态栏（`你自己也通关了…`）；小精灵通关仍然触发原来的结束面板，两边互不干扰。
- **双方死亡都复活重开**：谁摔了，谁回出生点并**重置自己那份进度**（原来只重置小精灵的，现在两边各自重置），另一边完全不受影响。小精灵摔了不再停下：45 帧（约 0.75 秒）后它自己复活继续闯（在调用上限内），人类摔了当帧复活，方便继续示范。跌落次数分开统计：`模型 N/16 次 · 小精灵跌落 X 次 · 你跌落 Y 次`，每次跌落与复活都写进学习日志。
- **日志挪到左边一列**：`/jump` 页面改成两栏，左栏是**常驻的深色日志列**（`position: sticky`，滚页面时它跟着停住），里面依次是「学习日志」和「它现在会什么」；右栏是游戏画面与控制。窄屏（<900px）自动堆叠成上下。实验室区里原来那两处折叠块已删除，不再有第二份。
- 你的示范现在**按你自己的规则重放**（`role: 'human'`），所以轨迹里会如实带上你顺手收的金币——这条也顺带成了"碰到金币会发生什么"的证据，小精灵可以从中读到物品机制。
- 「分屏：它上我下」保留；上一版加的「它摔了就自动重开一轮」被自动复活取代，已移除（手动「重开一轮（保留学习）」仍在）。

## 验证记录

- 自动化：194 项 Node 测试（新增 2 项：两个独立玩家各收各的、双方各自复活且只重置自己的进度；并把旧的两条"人类不能收金币"用例改写成"人类在自己的进度上收金币、且不碰小精灵的进度"）、40 项 Cloud 测试、`npm run check` 158 文件 0 失败、`npm run build` 通过。
- 页面夹具验证：人类走到金币上收到 1 枚而小精灵那份仍是 0；目标栏同时显示两边；人类死亡后回出生点、`humanFalls` 加 1、日志出现「你摔了」；小精灵死亡 45 帧后自动复活、位置与自己的进度重置、日志出现对应记录；你的示范轨迹里带上你收的金币。
- 未做：真实浏览器观感确认（左栏的 sticky 布局、深色配色只在夹具外无法验证）、线上发布。`test/life.test.mjs` 在本机偶发 `EPERM`/503（未改动的 main 上同样复现），与本改动无关。

## 限制与遗留问题

- **旧引擎没有同步**：`public/jump-engine.mjs`（v16 那套 JumpMemory/PetController，页面已不再加载，只有 `test/jump.test.mjs` 在用）仍保留"人类不能碰物品"的旧规则，它的测试也照旧。这是有意的：改它等于改一个已弃用引擎的行为，收益为零、风险不小。**线上跑的是 `jump-world.mjs`，也就是新规则。**
- 两边共享同一个世界、同一份"关卡状态"（门是否画成打开等视觉表现按各自进度分别绘制在各自的 HUD 里）；金币是每人一份，所以你们可以各自收同一枚。
- 分屏时画布高度翻倍，手机竖屏较占屏；左栏在窄屏会变成上方一栏，日志依旧可见。
- 复活延迟是固定 45 帧，不可配置。
