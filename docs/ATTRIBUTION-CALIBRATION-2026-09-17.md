# 归因层 + 标定层：学习回路的两个通用机制（2026-09-17）

## 诊断（统一抽象）

学习回路是 行动 → 结果 → **归因** → 规则 → 行动。之前两个"学不会"都是归因缺环：

- **金币学不会**：到了终点没通关，引擎知道缺什么但没有生成任何信号——信用分配链断裂。
- **跳水学不会**：规则学对了（"落在 x<489"），但"按几帧"没有数据源——符号规则落不到动作参数。

手写"终点事件""金币飞过事件""二分实验"是补丁：下一关出岩浆、移动平台就得再写一批。
所以做成两个通用机制。

## 层一：声明式交互表 + 通用近失归因

`public/jump-world.mjs` 新增 `interactables(level)`：每个可交互对象一行声明式记录
（区域 + 前置条件 + 效果 + 提示）。金币、机关、门、终点、双人压力板都是表里的行；
新机制加一行，不加事件代码。

`attributeAttempt(actor, level, bag, progress, ctx)` 是一条通用规则：

- 演员在效果未触发的情况下进入/经过对象区域 → 产出事件，机械列出**缺的前置条件**
  （"到了终点但没能通关：还缺 吃齐金币（还差 1 枚）"）；
- 前置条件齐全且在区域内 = 效果本帧将触发 → 不报（成功进行中，不是近失）；
- 从上方飞过（悬空经过）→ 报近失（"从金币附近经过但没吃到：要身体碰到才算"）。

客户端 `noteAttemptEvents`（`public/jump.mjs`）改为调用它，按对象 id 每次尝试去重。
原来的"飞过机关""被门挡住"手写事件被同一机制覆盖（门事件文案变为通用归因句式，
测试断言已改为语义而非文案）。

## 层二：标定预言机

"按住 N 帧跳多远"是引擎可精确回答的查询，从复盘时一次性粗测改为：

1. **决策时可用**：`planJump` 在宠物落地时自动附 `engineCalibration`——从当前位置
   实测"按住 N 帧（全程按右）落哪、会不会摔"，零 token，毫秒级。
2. **二分是通法**：粗网格 [1,10,20,30,45,60] 出现"安全→摔死"跳变时，在两者之间
   二分细测（≤6 次附加探测），并标注「最长安全按住」「再长就摔死」——一帧精度的
   可执行边界。任何"最大安全参数"问题都复用这个搜索。
3. 提示词说明：标定表是物理事实，选帧数以它为准；另补充 progress 字段语义与
   通关四要素（钥匙+机关+全金币+到终点）。

复盘提示词同步更新（实验含二分细测与边界标注）。复盘仍负责把实验数字上升为
scope「通用」的规则进通用手册（跨关继承，见 TWO-TIER-MEMORY-2026-09-17.md）。

## 未做（终态选项）

意图编译：模型只输出落点区间，引擎用有界搜索反解动作序列。可彻底消除
"知道规则却选错参数"这一类失败，但会削弱模型自己练操作的空间。待层一二
效果验证后再定。

## 验证指标

1. 近失事件覆盖率（未触发效果被归因的比例）；
2. "知道规则却选错参数"次数（目标趋 0）；
3. 到终点被拒 → 下次尝试行为改变的比例；
4. 新关卡首 5 次尝试的通用手册命中率。
