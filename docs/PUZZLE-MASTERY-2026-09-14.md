## 生成与验证

- 反向合法拉箱形成候选；标准 16 个候选，困难 / 难绕关键词 40 个。更高箱数使用更密的内部墙体限制开放空间的无效搜索。
- 按一次推动为一条搜索边的 BFS；同一箱子布局、同一人物可达区域合并。完整搜索成功时得到最少推箱数，步数不是最少走路数。
- 静态反向目标可达性与完整箱子/目标匹配用于必要条件剪枝；不能把通过这些检查当作全局有解。
- 生成筛选每题最多搜索 2,000（双箱）或 5,000（多箱）状态，模型独立验证保留现有 Node / Sites 有界预算。超预算与无解分别表示。
- 候选评分 = 推箱次数 + 3 × 解法换箱次数 + 5 × 推离目标次数；换箱/推离目标只描述这条验证解法，不宣称所有解法都必须如此，也不等于玩家难度或趣味性。
- 显式困难模式要求最少推箱数至少 `3 * boxes + 2`，即双箱 8、三箱 11、四箱 14。算法及模型均应用门槛，未达标时备题失败并保留原关。
- 标准模式无可用候选时可返回实际同规格的 algorithm-starter；来源标注保留。困难模式不会接受低于门槛的入门关。
- 模型提示携带地图尺寸和箱数；错误规格、有解但过简、验证失败可反馈并修复一次。验证仍失败不降级冒充模型关。

## 全链路兼容

真人键盘、触屏按钮、撤销、重来、回放与 AI 棋盘按动态地图宽度处理。逐步模型观察、目标坐标、候选推动、目标匹配和预演支持 2–4 箱；预演标签扩展 A–D。参赛模型不接收私有出题证明或评分路径。旧 8×8 双箱地图与已有比赛可继续使用。

双方 Node / Sites 使用相同成长、生成、操作与验证逻辑，D1 利用现有 JSON 列，无 SQL 迁移、不重写历史积分。四箱图搜索与模型闯关仍可能超时；未扩大比赛 180 秒时限。
