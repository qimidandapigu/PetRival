# PetRival · 宠物擂台

**宠物提前备好题，人和宠物一起挑战别人的宠物。**

独立像素风网页游戏。第一版专注推箱子：提前备题、挑战即开、真人操作、宠物自动闯关、计分和宠物排行榜。不是现有游戏的 Mod，也不是插件。

## 当前可用

- 领养一只宠物；每只宠物常备一张经过可解性验证的 8×8、双箱子关卡。
- 默认像素宠物“小汤圆”，也可选择芽芽灵、火花狐、云朵兽；支持逐像素编辑、改名、JSON / PNG 导入导出。
- 从宠物列表选择对手，立即使用双方缓存关卡开局。新题在后台生成，成功验证后才替换旧题；进行中的对局保持版本不变。
- 左侧宠物 AI、右侧真人同时挑战对方的题，各自操作和计分。AI 思考时真人即可操作，左侧实时显示已执行步骤。自己的守擂关也能人宠同时试玩，不计排名。
- 新增“一步一步试跑”：宠物每回合选择一次推箱子，走路工具负责到位，推完再观察；关闭思考，先在不计排名的试玩中体验。两张固定题真实测试均通关，首动约 1.6 秒，尚无稳定胜率结论。[试验记录](docs/STEP-PLAY-TRIAL-2026-09-13.md)。
- 方向键 / WASD 移动，Z 撤销，R 重来，也有屏幕方向按钮。
- 操作回放由服务端重放验证；胜负、分数、时间由服务端计算，不信任浏览器上报的“已通关”。
- 刷新后保留本地未提交操作；服务重启后保留身份、关卡、计时和历史成绩。
- 训练宠物用于一个人试体验，明确标注、不冒充真人、不进入正式排行榜。

当前交付是**可运行的本地原型**。已使用真实 DeepSeek Pro 完成一次生成和独立闯关，并通过浏览器验证左右同时操作。没有部署公网或 ChatGPT Sites，仍需真实玩家评价关卡是否好玩。详情见 [新版验收记录](docs/DEEPSEEK-PIXEL-ACCEPTANCE.md)。

## 启动

需要 **Node.js 24 或更新版本**，无第三方运行依赖，不需要先安装 npm 包。

```sh
git clone --branch codex/deepseek-pixel-release https://github.com/FromNextWorld/PetRival.git
cd PetRival
npm start
```

打开 <http://127.0.0.1:4388>。默认只监听本机。

本次开发实例使用独立端口 **4473**，打开 <http://localhost:4473>，避免改动此前 4388 上的算法试玩和存档。复制 `.env.example` 为 `.env` 并填写自己的 Key 后重启，即可使用 DeepSeek Pro；未配置 `.env` 时仍是可离线玩的算法模式。

在两个不同浏览器或普通 / 无痕窗口中，各领养一只宠物，就能测试两个独立主人的异步对抗。同一浏览器的普通标签页共享访客身份。

```sh
npm test
npm run check
```

`npm run check` 检查 JavaScript 语法和常见密钥模式；不是完整安全审计。当前没有配置 GitHub Actions 或分支保护硬门禁。

## 挑战与排名规则

1. 领养时勾选异步守擂，表示允许其他宠物直接发起挑战。对方不用同时在线。
2. 一场对局包含两张锁定版本的关卡；A 的主人和宠物挑战 B 的题，B 的主人和宠物挑战 A 的题。自家题的练习不计入正式成绩。
3. 真人点击进入挑战才开始自己的 3 分钟计时。撤销、重来、关闭和刷新都不重置计时。
4. 每次通关 **+100**，失败 / 认输 / 超时 **−20**。一方的分数是主人与宠物之和。模型返回非法操作也算宠物失败。
5. 同分比较计分用时。真人用服务端经过时间；宠物包括排队、思考、实际执行的总耗时，每条动作按 220ms 执行，时间只计算一次。失败统一按 180 秒计入比较，不能靠秒退获得时间优势。
6. 双方主人与宠物全部完成后，才结算一次并更新宠物累计分、胜负和排行榜。同分按累计计分用时排序。这是简单原型积分，不是经过平衡的竞技评级。
7. 玩家可以边玩边看自己宠物的实时步骤；完成后也能看完整回放。对手路线在自己结束前保密。参赛宠物只收到当前地图，不收到出题证明、其他宠物的对话或真人操作。
8. 未在 24 小时内完成的对局作废，不计分。模型服务掉线、服务重启打断 AI 等基础设施故障也作废并保留已执行记录，不重置计时后重赛。模型思考超过比赛时限、给错操作或未解出则是正常失败。
9. 同一对手同时只能有一场有效挑战，每只宠物同时最多三场；同一组关卡版本不能重复计分。

训练宠物没有真人主人，所以训练赛只显示体验分，不虚构对方真人成绩，也不改变排行榜。

## AI 模式

### 无密钥的算法模式（默认）

程序化反向打乱生成关卡，独立的有界搜索验证可解性。参赛宠物重新独立搜索，并由统一游戏引擎执行操作。

这是**经典算法 AI，不是大语言模型**。简单的“难 / 绕”关键词改变生成参数，不具备任意自然语言设计理解；也尚未接入外部的关卡好玩优化研究框架。

### DeepSeek Pro 模式

将 `.env.example` 复制为本机 `.env`，在编辑器或密钥管理环境中填写：

```dotenv
AI_MODE=model
MODEL_CHAT_URL=https://api.deepseek.com/chat/completions
MODEL_NAME=deepseek-v4-pro
MODEL_API_KEY=your-local-secret
MODEL_TOKEN_PARAMETER=max_tokens
MODEL_PLAY_EFFORT=high
```

不要把真实密钥发到聊天、写进前端或提交到 Git。此仓库默认忽略 `.env` 与运行数据。

DeepSeek 出题固定使用高思考，闯关由 `MODEL_PLAY_EFFORT=high|low|none` 控制，默认仍为 `high`。`none` 关闭闯关思考，模型仍为 Pro；三档均使用 `max_tokens: 16384`。修改配置后需要重启服务才会用于新运行，正在进行的挑战不应为换配置而中断。Key 仅由服务端读取，不返回给浏览器或写入外观文件。算法求解器只负责独立验证关卡；比赛动作来自模型本次的规划。

也保留兼容 Chat Completions 供应商适配：要求支持 `messages`、`response_format: {type: "json_object"}` 和 `choices[0].message.content`；可将 Token 参数改为 `max_completion_tokens`。这不等于所有供应商都已测试。

- 出题：给模型可编辑的关卡骨架和用户要求；返回结构化地图。失败时提供验证错误并最多修复一次。仍未通过就保留旧关，不偷偷替换成算法题并声称模型成功。
- 闯关：只给当前地图，每次最多 120 个方向动作、最多三轮规划。真实引擎判定结果，不采信模型自称通关。
- 调用上限：出题请求最多 240 秒；AI 整场闯关最多 180 秒，包含排队、规划和执行。闯关最多并行 2 个、备题最多并行 1 个，分别排队且各最多 16 个等待任务；后台备题不占用闯关通道。搜索任务单次 15 秒，并行 2 个、队列最多 32 个。
- 第一次领养时先分配已验证的算法入门关，让玩家立即可玩；配置的模型在后台生成替代关卡。每一关标明实际来源。
- 外部模型供应商将收到设计要求和关卡数据。当前没有将反馈用于训练、出售数据或后台收集用户私人内容的功能。

协议参考：[DeepSeek 官方接入文档](https://api-docs.deepseek.com/zh-cn/)及[思考模式参数](https://api-docs.deepseek.com/guides/thinking_mode/)。一次成功样本不代表所有关卡都能在时限内解出。

### 同题思考强度评测

固定样本保存在 `test/fixtures/play-effort-levels.json`，包含 8 张既有模型关和 2 张训练关。运行下面的命令会使用本机 `.env` 中的 Key，真实调用 Pro 完成 30 场独立试验（每场最多 3 轮规划）；不修改游戏存档或榜单。

```sh
node --env-file=.env scripts/benchmark-play-effort.mjs --run
node scripts/summarize-play-effort.mjs --write-report
```

原始记录写入忽略提交的 `.artifacts/effort-benchmark/results.json`，包含真实动作和数值用量，不包含凭据或思考正文。已有结果时脚本拒绝覆盖，避免把复测偷偷替换成最好的一次。只有 30 场完整结束并覆盖全部题目和模式组合，才允许生成完整报告。首步统计排除撞墙，通关由生产游戏引擎确认；失败和服务异常分别保留。

[2026-09-13 真实对比](docs/PLAY-EFFORT-BENCHMARK-2026-09-13.md)：高思考 9/10 通关、首动中位数 80.70 秒；低思考 10/10、61.26 秒；关闭思考 0/10。当前本机 4473 试用 low，出题保持 high，仓库默认仍为 high。该小样本显示低思考有改善，但尚未达到几秒首动。

## 自己设计像素宠物

在自己的宠物卡片点击“编辑外观 / 导入导出”。可以选预设、改名、调色，用画笔和橡皮画 16×16 像素，也可撤销和恢复预设。

- JSON 保存名字、类型和每个像素，导出后可以完整导入；不会复制账号、积分、排名、关卡或密钥。
- PNG 导出 16×16 透明图，支持导入 16–256 像素的正方形 PNG，按最近邻缩成 16×16。半透明像素以透明度 128 为阈值转换。
- 导入先预览，点击保存才应用。只允许修改自己的宠物；旧存档没有外观字段时自动使用原种类预设。

## 文件结构

```text
public/             页面、双棋盘、外观编辑器（原创 SVG / Canvas 像素角色）
shared/game.mjs     同一套移动、回放、求解、生成与计分规则
shared/pet.mjs      像素预设、安全渲染与外观文件校验
server/             HTTP、访客身份、持久化、宠物竞技、后台任务、模型适配器
test/               规则、真实 HTTP 链路、外部模型模拟、页面事件回归
docs/               任务约定与验收记录
data/               本地运行存档，忽略上传
```

## 上线前仍需完成

- 这是**单 Node 进程、单机 JSON 存档**，不要让多个进程共用同一个 `DATA_DIR`。原子替换可避免半写文件，但不是多副本数据库或完善备份系统。
- 尚无正式账号、找回身份、强反作弊、反刷分、完整运维与容量压测。浏览器操作回放验证不能证明操作者一定是真人；熟悉同一道题也可能带来优势。
- 访客 Cookie 丢失后无法恢复所有权；服务器保存会话散列、宠物、题目及对战回放。本地数据和日志不上传仓库。
- 存档尚无自动清理与归档；长期运行需要数据库、过期数据策略、监控和服务端部署。
- 公网发布前需要 HTTPS、`COOKIE_SECURE=1`、正式身份系统、稳定的模型配额与费用限制、数据告知和负载测试。
- 没有会员、充值、语音、养成树，也没有把这个 Node 服务直接部署到 ChatGPT Sites。不存在已经验证的并发容量承诺。

详细证据见 [验收记录](docs/ACCEPTANCE.md)。
